# 对标 Photoshop 的完成度（2026-10-23 定稿）

> 目的：回答「这个项目现在能当 Photoshop 用吗」，给一个可复核、可拆分的数字。
> 证据全部来自当前工作树（HEAD `087f7bc` + P0-6 ① 未提交批次）的实测与代码计数；
> 缺口清单与逐条证据见仓库根 `BACKLOG.md`，本文件只做**计分与汇总**。

---

## 0. 结论：四个数字，四个分母

| 口径 | 分母 | 数字 | 回答的问题 |
|------|------|------|-----------|
| A 引擎核 | 引擎 + ABI + 两壳的契约、像素保真、跨端交付 | **≈97%** | 内核做完了吗 |
| B 上游功能条目 | 上游 Compositor README 的 48 条 | **≈60%**（29/48） | 与上游对等了吗 |
| C Photoshop 日常使用路径 | PS 高频操作（按使用频率加权） | **≈70%** | 日常干活够不够用 |
| D Photoshop 全功能面 | PS 核心功能条目（190 条） | **≈50%**（加权） | 功能面整体差多少 |

**四个数字不矛盾**：A 问内核保真，B 问与上游产品的条数差，C 问高频路径，D 问完整功能面。
对外只报一个数时，用 **「日常路径 ≈70%，全功能面 ≈50%」**，不要用 97%——那会把内核完成度
误读成产品完成度。

## 3. 与历史数字的关系

| 历史数字 | 出处 | 今天怎么读 |
|---------|------|-----------|
| 口径 A ≈97% | README §6.4（2026-10-17） | 仍成立；P0-1～P0-10 与 P1 各批只增加产品通路，没有削弱内核契约 |
| 口径 B ≈60%（29/48） | README §6.4 | 仍成立，但**分母是上游 Compositor，不是 PS**；用它回答「能当 PS 用吗」会系统性高估（BACKLOG §8 已记这条漂移） |
| 96.75% / 60% 的算术 | README §6.4 | 是当时的实测记录，不改写；新口径以本文件为准 |

**为什么全功能面只有 50% 而日常路径有 70%**：PS 的功能条目长尾极重——滤镜 100+、
调整 20+、色彩管理、打印、自动化、3D/视频/画板。这些条目数量大、日常频率低。
本仓在「高频主干」上覆盖得比「条目总数」好，所以两个数字差 20 个点，属预期而非矛盾。

## 4. 剩余缺口的 ROI 排序（按「每投入一天抬高多少日常得分」）

| 顺位 | 缺口 | 性质 | 对日常得分的影响 | 依据 |
|------|------|------|----------------|------|
| 1 | 字体枚举与选择器 | 【壳层】S–M | 文字维 55% → 75% | 随包字体只有一个，`comp_font_load_file` 已能加载任意 TTF，缺枚举/回退链（BACKLOG P1-4、P0-6②） |
| 2 | 锐化 / 降噪 / 高斯模糊入口 | 【接线】S | 调整滤镜维 55% → 70% | 高斯模糊、动感模糊已是调整层；锐化/降噪需新像素实现，属 M |
| 3 | 标尺 / 参考线 / 网格 / 对齐 | 【壳层】M | 视图维 60% → 80% | 纯外壳与文档模型，ABI 可零新增（参考线进 `.comp` 需尾字段） |
| 4 | PSD 分层导出 | 【引擎】L | 文档维 70% → 85% | 交付刚需；需先定第三方库策略（BACKLOG P0-7） |
| 5 | 存储/载入选区通道 | 【ABI 追加】+【引擎】M | 选区维 80% → 90% | 通道是新文档模型，需 `.comp` 持久化 |
| 6 | 组混合模式 + Pass Through | 【引擎】S–M | 图层维 85% → 90% | 当前组强制 Normal（`comp_file.cpp:285`），Pass Through 应成为显式枚举 |
| 7 | HiDPI（manifest + `SetProcessDpi*`） | 【壳层】S | 视图维 60% → 70% | 现在靠系统位图拉伸，200% 缩放下 1px 线不再是 1 设备像素 |
| 8 | 破坏性 Image > Adjustments 族 | 【ABI 追加】+【引擎】M | 调整维 55% → 65% | 多数可复用 `AdjustPixels`；现在只有反相 |

不推荐现在做：色彩管理 / 打印 / 自动化 / 多文档 / 3D·视频。它们是独立子系统，
在「日常路径」权重里合计不足 5%，投入产出比最差（BACKLOG §7 阶段 G）。

## 6. 一句话结论

**内核（97%）已经做完，产品功能面（50%）还差一半；差的不是像素算法，而是把已有能力
做成用户路径。** 按 ROI 顺序补前 4 项（字体选择、锐化/降噪入口、标尺参考线、PSD 导出），
日常路径可从 70% 推到约 85%，这是「能当 PS 用」的实际门槛。
