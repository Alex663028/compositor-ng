# 对标 Photoshop 的完成度（2026-10-23 定稿）

> 目的：回答「这个项目现在能当 Photoshop 用吗」，给一个可复核、可拆分的数字。
> 证据全部来自当前工作树（HEAD `087f7bc` + P0-6 ① 未提交批次）的实测与代码计数；
> 缺口清单与逐条证据见仓库根 `BACKLOG.md`，本文件只做**计分与汇总**。

## 0. 结论：四个数字，四个分母

| 口径 | 分母 | 数字 | 回答的问题 |
|------|------|------|-----------|
| A 引擎核 | 引擎 + ABI + 两壳的契约、像素保真、跨端交付 | **≈97%** | 内核做完了吗 |
| B 上游功能条目 | 上游 Compositor README 的 48 条 | **≈60%**（29/48） | 与上游对等了吗 |
| C Photoshop 日常使用路径 | PS 高频操作（按使用频率加权） | **≈78%** | 日常干活够不够用 |
| D Photoshop 全功能面 | PS 核心功能条目（190 条） | **≈62%**（加权） | 功能面整体差多少 |

**四个数字不矛盾**：A 问内核保真，B 问与上游产品的条数差，C 问高频路径，D 问完整功能面。
对外只报一个数时，用 **「日常路径 ≈78%，全功能面 ≈62%」**，不要用 97%——那会把内核完成度
误读成产品完成度。

## 3. 与历史数字的关系

| 历史数字 | 出处 | 今天怎么读 |
|---------|------|-----------|
| 口径 A ≈97% | README §6.4（2026-10-17） | 仍成立；P0-1～P0-10 与 P1 各批只增加产品通路，没有削弱内核契约 |
| 口径 B ≈60%（29/48） | README §6.4 | 仍成立，但**分母是上游 Compositor，不是 PS**；用它回答「能当 PS 用吗」会系统性高估（BACKLOG §8 已记这条漂移） |
| 96.75% / 60% 的算术 | README §6.4 | 是当时的实测记录，不改写；新口径以本文件为准 |

**为什么全功能面只有 62% 而日常路径有 78%**：PS 的功能条目长尾极重——滤镜 100+、
调整 20+、色彩管理、打印、自动化、3D/视频/画板。这些条目数量大、日常频率低。
本仓在「高频主干」上覆盖得比「条目总数」好，所以两个数字差 20 个点，属预期而非矛盾。

## 6. 一句话结论

**内核（97%）已经做完，产品功能面（62%）还差三成；差的不是像素算法，而是把已有能力
做成用户路径。** ROI 前 8 项——字体选择（§6.89）、锐化/降噪入口（§6.90）、
标尺/参考线/网格/对齐（§6.91）、PSD 分层导出（§6.87）、存储/载入选区通道
（§6.92）、组混合模式（§6.87）、HiDPI（§6.93）与破坏性 `Image > Adjustments`
（§6.94）——已全部落地，随后的调整族补全（§6.95）把 `图像 > 调整` 铺满 20 项，
段落框与对齐（README §6.99）补上长文案排版，画笔预设/流量/压感（README §6.100）
把 `desc.brush` 里闲置的 `pressure` / `flow` 接进选项栏，变换选区（README §6.102）
把手柄缩放补成带数值与旋转的命令，数值变换 + 再次变换（README §6.103）把图层的
「精确尺寸」与「复读上一步」补进菜单，图案叠加（README §6.104）把 10 种图层样式
的最后一块补齐，P1-2 八批（锁/标签 §6.106、合并可见/反向排列 §6.107、图层链接
§6.108、样式拷贝/粘贴 §6.109、面板过滤 §6.110、图层复合 §6.111、智能对象/智能滤镜
§6.112、填充层 §6.113）把图层面板整个收齐——连 PS 里最「重」的两件（智能对象、
图层复合）都在：
日常路径 70% → **78%**，全功能面 51% → **62%**。
HiDPI 抬的更多是「用起来像不像 PS」（文字与分隔线在 150%/200% 屏上终于是原生像素），
不是条目数；破坏性调整则是把「PS 里最顺手的一条路」补上。再往上要靠画笔动态、
竖排/文字变形这些「单条分值低、条目却多」的活，日常路径的天花板约在 80%。
